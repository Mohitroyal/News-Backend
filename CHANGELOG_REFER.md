## 1. Backend Changes (`News-Backend` / `main` branch)

### A. Summary & Key Takeaways Target Language Enforcement ([grok_service.py](file:///c:/Users/MOHIT/Desktop/newscraft-mobile/app/services/grok_service.py))
- **Strict Language Requirement**: Added system and user prompt enforcement requiring `summary` and `bullet_points` to be generated strictly in the selected target language (`te` for Telugu, `hi` for Hindi, `kn` for Kannada, `ta` for Tamil, `ml` for Malayalam).
- **English Leakage Interception**: Implemented `_is_mostly_english(data)` detection. If the LLM returns English words for a non-English clipping, the system automatically replaces them with clean target-language extraction from the article's translated `sections`.
- **Abbreviation Protection**: Upgraded sentence splitting regex (`re.sub(r'(\b[^\s\.]{1,4})\.\s+', r'\1_DOT_ ', text)`) to protect single-letter and short Indic abbreviations (e.g., Telugu `ఆర్.`, `టి.`, `ఐ.`, `డా.`, `శ్రీ.`, `బి.`, dates like `జులై 26`). Prevents Telugu text from being sliced into tiny 2-letter fragments.
- **Rich Content Output**: Configured extraction and AI prompts to generate a **detailed summary paragraph (~350–450 characters)** and **4–5 complete key takeaway bullet points**.

### B. Localized Box Headings in Layout Engine ([render_service.py](file:///c:/Users/MOHIT/Desktop/newscraft-mobile/app/services/render_service.py))
- Section box headings dynamically translate based on `data.language` or `data.language_name`:
  - **Telugu (`te`)**: `సారాంశం` (Summary) & `ముఖ్య అంశాలు` (Key Takeaways)
  - **Hindi (`hi`)**: `सारांश` & `मुख्य बिंदु`
  - **Kannada (`kn`)**: `ಸಾರಾಂಶ` & `ಪ್ರಮುಖ ಮುಖ್ಯಾಂಶಗಳು`
  - **Tamil (`ta`)**: `சுருக்கம்` & `முக்கிய அம்சங்கள்`
  - **Malayalam (`ml`)**: `സംഗ്രഹം` & `പ്രధాన വിവരங்கள்`
  - **English (`en`)**: `SUMMARY` & `KEY TAKEAWAYS`
- Passed `"language"` explicitly into `serializable_data` payload for client-side layout rendering.

### C. Groq / xAI Model Resiliency ([grok_service.py](file:///c:/Users/MOHIT/Desktop/newscraft-mobile/app/services/grok_service.py))
- Lowered `max_tokens` to `2500` so total requested tokens stay below Groq's 6,000 TPM limit.
- Implemented model fallback sequence (`grok-2-1212` -> `grok-2` -> `llama-3.1-8b-instant` -> `llama-3.3-70b-versatile`) with graceful local fallback if API rate limits occur.
