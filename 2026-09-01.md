## 1. Reporter Profile Photo & Name Persistence (Top-Left Badge)
- **Feature**:
  - Automatically displays the user's reporter profile photo (circular badge) and reporter name in the top-left header across all clipping templates.
  - When the user selects or updates their profile picture during login or in settings, it is persistently tied to their account and automatically injected into every clipping generation without needing to be re-uploaded each time.
- **Affected Templates**:
  - `app/renderer/templates/rti_express/template.html`
  - `app/renderer/templates/bharath_reporter/template.html`
  - `app/renderer/templates/national_news/template.html`
  - `app/renderer/templates/hero_image/template.html`
  - `app/renderer/templates/custom/template.html`
  - `app/renderer/templates/master_layout.html`
- **Backend Pipeline**:
  - In `app/api/v1/endpoints/generate.py`, `reporter_name` and `reporter_image` are retrieved from user profile metadata and forwarded into `render_data`.

## 2. Pattern G: Dynamic Single Image (Left 75% Height Layout)
- **Feature**:
  - Added a new single-image layout **Pattern G** to the Single Image selection section in both frontend and backend.
- **Visual & Layout Mechanics**:
  - **Left Side 75% Height**: The image occupies the left 0 to 75% height of the clipping content canvas.
  - **Dynamic Aspect Ratio Width**: Instead of a static width, the image width dynamically scales with its aspect ratio (`aspect0`), clamped between 38% and 52% of canvas width.
  - **Text Flow & Column Ordering**:
    - Right side columns flow top-to-bottom next to the image.
    - Remaining article text flows below the image across the bottom 25% area.
  - **Whitespace Elimination (Shrink-Wrapping)**:
    - Auto-adjusts canvas height to shrink-wrap tightly around the bottom of the article text without awkward empty gaps.
  - **Cross-Template Compatibility**:
    - Seamlessly supported across RTI Express, Bharath Reporter, National News, Hero Image, and Custom Newspaper templates.
- **Frontend Changes**:
  - Updated `PatternSelectionModal.tsx` and `TemplatesScreen.tsx` with Pattern G option (`patternId: 'G'`).

## 3. Fixed Default Template Fallback Crash (`ReferenceError: aspect0`)
- **Bug Fixed**:
  - When a user submitted article text and images without picking a specific layout (relying on default/auto fallback), clippings failed to generate, resulting in an empty white canvas below the headline.
- **Root Cause**:
  - `aspect0` was referenced in `getObstacles()` across fallback branches without a variable declaration, causing a JavaScript `ReferenceError: aspect0 is not defined` inside headless Playwright.
- **Fix**:
  - Added safe initialization `const aspect0 = (aspectRatios && aspectRatios.length > 0 && aspectRatios[0]) ? aspectRatios[0] : 1.33;` at the entry point of image obstacle processing in `app/services/render_service.py`.

---

## 4. Zero Secondary Cropping for User-Cropped Images
- **Bug Fixed**:
  - When users cropped images in the mobile app's crop box (e.g. 16:9, 4:3, 3:2, 1:1), the backend full-image renderer was re-cropping the top and bottom of the image.
- **Root Cause**:
  - Full-image / hero layout was hardcoded to `Math.min(dynamicH, 350)` and caption allowance was deducted directly from image height with `object-fit: cover`, squashing standard landscape images into a panoramic strip and chopping off top/bottom sections.
- **Fix**:
  - Removed artificial 350px height cap in favor of natural aspect-ratio height (`W_canvas / aspect0`), allowing up to 65% canvas height.
  - Assigned dedicated vertical allowance for captions separate from image height.
  - Configured exact aspect ratio matching with `object-fit: contain` and centered positioning so **100% of the user-cropped box is preserved without any cropping**.
